# Release Notes - OpenPDF 3.0.7

This is a security release. It fixes two problems in signature verification that let a forged or modified document pass as valid, hardens the readers for PDF files, images, fonts and HTML against malformed input, and stops documents from making the library read local files or fetch URLs in unexpected ways. It also adds support for reading PDF files larger than 2 GB.

OpenPDF 3.0.x requires Java 21 and is maintained in the `3.0-java21` branch.

## ⚠️ Upgrade Notes

### Signature verification is stricter
* **Byte range (PR #1692).** `AcroFields.verifySignature` now throws for a signature whose `/ByteRange` does not have the form of a signature over a document: exactly two ranges, the first one starting at the beginning of the file, with nothing but the signature value between them. `signatureCoversWholeDocument`, `getRevision`, `getTotalRevisions` and `extractRevision` are derived from the end of the signed range. `extractRevision` returns `null` for a signature with an invalid byte range.
* **Certificate chains (PR #1694).** `PdfPKCS7.verifyCertificates` verifies the **first** certificate of the array and validates its certification path with the PKIX algorithm. The other certificates are only used as intermediate certificates. `PdfPKCS7.getCertificates()` now returns the signing certificate first, so existing callers verify the signer without changing their code. Certificates issued by a certificate that is not a certification authority are rejected.
* **Embedded OCSP responses (PR #1733).** `PdfPKCS7.isRevocationValid()` now also requires that the response says the certificate is good and that it is signed by the issuer or by a responder the issuer authorised. With the default provider this method always returned `false` before; that is fixed.
* **OCSP and TSA clients (PR #1696).** `OcspClientBouncyCastle` only returns a response that is about the requested certificate and is signed by the issuer or an authorised responder. Both clients only connect to `http` and `https` URLs, time out after 30 seconds and reject responses larger than 1 MB.
* **VeriSign filter (PR #1704).** Signatures created with `PdfSignatureAppearance.VERISIGN_SIGNED` use SHA-256 instead of MD5.

### Other behaviour changes
* **HTML to PDF: `onclick` (PR #1715).** The `onclick` attribute of an internal link is no longer written into the PDF as a JavaScript action. Call `ITextOutputDevice.setOnclickJavaScriptEnabled(true)` to get the old behaviour.
* **HTML to PDF: presentational attributes (PR #1721).** Values of attributes such as `width`, `height`, `colspan`, `bgcolor`, `align` and `background` are validated before they become CSS. Values that are not a single valid CSS value, for example `width="50%;"`, are ignored.
* **HTML to PDF: limits (PR #1725, #1729).** `colspan` is limited to 1000, `rowspan` to 65534 and `tab-size` to 64. CSS imports are followed at most 16 levels deep, and a stylesheet that imports itself is read once.
* **HTML to PDF: redirects (PR #1711).** HTTP redirects are only followed to `http` and `https` URLs, at most 5 times. Override `NaiveUserAgent.isRedirectAllowed` to restrict the hosts.
* **HTML to PDF: XML parsing (PR #1707).** `Java2DRenderer.htmlAsImage` and `XMLUtil` no longer read external entities or external DTDs. The DTDs bundled with the library are used for XHTML documents.
* **Font names from documents (PR #1698).** A font name that comes from a WMF image or from HTML handled by `HTMLWorker` is only looked up among the registered and built-in fonts. It is no longer opened as a font file or URL. `FontFactory.getFont` is unchanged for applications that pass a font path themselves.
* **`HtmlWriter` (PR #1746).** Attribute values such as `href`, `src` and `alt` are escaped. A value that was already escaped by the caller is now escaped twice.
* **RUPS (PR #1736).** An XFA form with a DOCTYPE declaration is no longer shown.
* **File offsets are now `long` (PR #1591).** To support files larger than 2 GB, several methods and fields changed from `int` to `long`:
    * `RandomAccessFileOrArray`: `length()`, `getFilePointer()`, `getStartOffset()`, `setStartOffset(long)`
    * `PRTokeniser`: `seek(long)`, `getFilePointer()`, `length()`, `getStartxref()`
    * `PdfReader`: `getLastXref()`, `getEofPos()`, `getFileLength()`, and the protected fields `xref` (`long[]`), `lastXref`, `eofPos` and `objStmToOffset` (`Map<Integer, Long>`)
    * `PRStream`: `getOffset()` and the constructor `PRStream(PdfReader, long)`

  Code that stores these values in an `int` needs a cast, and code compiled against an earlier version must be recompiled.
* **brotli4j is now an optional dependency (PR #1590).** It is no longer pulled in transitively. Projects that read or write Brotli-compressed PDFs must add `com.aayushatharva.brotli4j:brotli4j` themselves.

## 🔒 Security

### Digital signatures
* **Modified documents:** A signed PDF could be changed after signing and still verify, and still be reported as covering the whole document, because the byte range of the signature was not validated (PR #1692).
* **Certificate chains:** `PdfPKCS7.verifyCertificates` accepted a chain as soon as any certificate in it was trusted, and accepted certificates issued by a certificate that is not a certification authority (PR #1694).
* **Revocation:** Embedded and fetched OCSP responses are now checked for their status, their subject and their signature (PR #1696, #1733).
* **Documentation:** The Javadoc of `PdfPKCS7` now says that `verify()` only checks the integrity of the signed bytes, that the signing date and the timestamp date are not authenticated, and that certificate revocation lists are used as they are (PR #1704).

### Reading local files and fetching URLs
* **XML external entities:** `Java2DRenderer.htmlAsImage`, `XMLUtil` and the XFA viewer of RUPS could read local files or fetch URLs through external entities (PR #1707, #1736).
* **Redirects:** `NaiveUserAgent` followed redirects to any protocol, for example to `file:` URLs (PR #1711).
* **Font names:** A font name in a WMF image or in HTML could make the library open a file or URL (PR #1698).
* **Generated HTML:** Links from a PDF were written into the HTML of the HtmlBookmarks tool without escaping (PR #1746).

### Malformed input
Small malformed files could make a thread run forever, overflow the stack or allocate gigabytes of memory. Such files are now rejected:
* **PDF files in `openpdf-core`:**
    * Cycles in cross-reference chains (PR #1709), page trees (PR #1720), form fields, outlines, name trees and number trees (PR #1723).
    * Sizes of cross-reference tables, cross-reference streams and object streams that the file cannot hold (PR #1713).
    * Arrays and dictionaries nested more than 512 levels deep (PR #1717).
    * Form XObjects that draw themselves, unterminated CMaps and oversized width ranges during text extraction (PR #1727).
    * Invalid PNG predictor parameters (PR #1731).
    * Streams whose dictionaries share objects at several levels, which made `PdfSmartCopy` use exponential time and memory (PR #1753).
* **Images and fonts:** Truncated JPEG 2000 files (PR #1699), WMF records whose counts exceed the record (PR #1703), and sizes, ranges and subroutine calls in TrueType, TrueType collection and CFF fonts (PR #1701).
* **PDF files in `openpdf-renderer`:** Cycles in cross-reference chains (PR #1738), exponential parsing time for nested arrays (PR #1740), invalid predictor parameters (PR #1742), and forms, page trees, images, name trees and functions that refer back to themselves. A parser that fails no longer leaves threads waiting for the page (PR #1744).
* **PDF files in `openpdf-renderer`, `OpenPdfCoreRenderer`:** Form XObjects that draw themselves (PR #1755).
* **PDF files in `openpdf-renderer`, `OpenPdfCoreRenderer`:** Form XObjects that draw each other so often that rendering a page does not end. Rendering of a page stops after 20 million operators (PR #1757).
* **PDF files in `openpdf-renderer`, `OpenPdfCoreRenderer`:** Images that declare a size whose number of bytes does not fit in an `int`, which reserved gigabytes of memory for an image without data (PR #1759).
* **PDF files in `openpdf-renderer`, `OpenPdfCoreRenderer`:** JPEG and JPEG 2000 images whose header announces a very large size. Such images are only decoded up to 100 million pixels, and only by a JPEG or JPEG 2000 reader (PR #1761).
* **HTML in `openpdf-html`:** Long runs of white space in a text node, which took time that grew with the square of their length. The field `WhitespaceStripper.linefeed_space_collapse` is deprecated (PR #1763).

### Other
* **Encryption:** `PdfWriter.DO_NOT_ENCRYPT_METADATA` no longer silently switches to embedded-files-only mode, which left all stream and string content unencrypted (PR #1589, fixes #1576).
* **Code Scanning:** Resolved the open code scanning alerts and the bugs and security hotspots reported by SonarCloud (PR #1678, #1679).

OpenPDF is still not a sandbox. Applications that process untrusted input have to limit its size and sanitise untrusted HTML, see [Security.md](../Security.md).

## 🌟 New Features & Enhancements
* **Large Files:** `PdfReader` can now read PDF files larger than 2 GB. File positions are tracked as 64-bit offsets throughout the read path (PR #1591, fixes #1582).
* **Brotli:** `DecodeParms` are now applied after `/BrotliDecode`, so predictor-encoded Brotli streams are decoded correctly (PR #1674, fixes #1654).
* **Predictors:** The shared predictor decoder now reconstructs TIFF predictor 2 for 1-, 2-, 4-, 8- and 16-bit components. This also applies to `/FlateDecode` and `/LZWDecode` streams (PR #1674).
* **Text Extraction:** Parsed fonts are cached while a content stream is processed (PR #1595, fixes #1268).

## 🛠 Bug Fixes
* **PdfReader:**
    * A corrupt cross-reference stream that points at an object stream outside the document no longer causes an `IndexOutOfBoundsException` (PR #1602, fixes #1601).
    * An `/Encrypt` entry in the trailer that cannot be resolved is treated as an unencrypted document (PR #1593, fixes #1588).
    * Permissions (`/P`) that are written as an unsigned 32-bit number are handled in encrypted PDFs (PR #1592, fixes #1585).
    * The PNG Average predictor is now computed from unsigned neighbouring bytes, and the bytes-per-pixel value is rounded up for samples smaller than one byte (PR #1674).
* **Images:** The palette of 1-bit indexed images is preserved; such images were rendered inverted (PR #1597, fixes #1534).
* **Barcodes:** EAN-13, UPC-E and Data Matrix now reject values that would be silently encoded as a different value (PR #1675).
* **Text Extraction:** Fixed a context stack exception in `PdfTextLocator` for PDFs without a context, and improved text measurement and matching (PR #1538).
* **Dependencies:** A transitive brotli4j no longer triggers an `UnsatisfiedLinkError` in libraries that detect it on the classpath, such as Apache HttpClient 5 (PR #1590, fixes #1584).
